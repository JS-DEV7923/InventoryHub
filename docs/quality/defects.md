# InventoryHub Defects and Quality Gaps

## DEF-001

- Severity: BLOCKING
- Summary: Runtime implementation does not use AWS SNS/SQS retries or DLQs.
- Requirement impacted: REQ-018, AC-020, AC-021.
- Evidence: The application uses Spring in-process events in `DomainEventPublisher`; Terraform defines queues and DLQs, but the runtime is not wired to AWS messaging.
- Expected: Failed asynchronous message processing is retried and eventually succeeds or moves to a DLQ.
- Actual: Local event handlers run in-process; there is no runtime SQS visibility timeout, redrive policy, or DLQ path.
- Release impact: Blocks production release against the full event-driven reliability spec.
- Recommended fix: Add SNS/SQS adapters and Localstack/AWS integration tests for retry and DLQ behavior.

## DEF-002

- Severity: HIGH
- Summary: Unknown product in order creation likely returns `404`, but the contract requires `400`.
- Requirement impacted: REQ-007, AC-007, API contract.
- Evidence: `OrderService.createOrder` calls `catalogService.findProduct` directly; missing products throw `NotFoundException`. API contract states `400` for unknown product in `POST /api/orders`.
- Expected: Unknown product in order payload returns HTTP 400 with structured field error.
- Actual: Static review indicates HTTP 404.
- Release impact: Client contract mismatch for order validation.
- Recommended fix: Convert missing product during order validation to `ValidationException` and add API test.

## DEF-003

- Severity: HIGH
- Summary: Conflicting idempotency-key payloads are not rejected.
- Requirement impacted: REQ-007 and API contract.
- Evidence: `OrderService.createOrder` returns the existing order for any repeated `Idempotency-Key` without comparing payload.
- Expected: Duplicate key with conflicting payload returns HTTP 409.
- Actual: Existing order is returned regardless of request body.
- Release impact: Clients can receive an order created for different line items or customer input.
- Recommended fix: Store request fingerprint with idempotency key, compare on reuse, and return 409 for conflicts.

## DEF-004

- Severity: HIGH
- Summary: Inventory oversell prevention is not proven by concurrency tests.
- Requirement impacted: REQ-012, AC-015, RISK-001.
- Evidence: Pessimistic locking and version fields exist, but no test exercises concurrent reservation attempts.
- Expected: Concurrent orders cannot create negative inventory.
- Actual: Not tested.
- Release impact: Inventory correctness is a core system promise; production release needs proof.
- Recommended fix: Add MySQL-backed or Testcontainers concurrency test with competing reservations.

## DEF-005

- Severity: MEDIUM
- Summary: Database migrations are missing.
- Requirement impacted: REQ-021 and launch readiness checklist.
- Evidence: Spring config uses Hibernate `ddl-auto: update`; no Flyway or Liquibase migrations are committed.
- Expected: Repeatable committed migrations create required tables.
- Actual: Schema is generated by Hibernate.
- Release impact: Schema changes are not production-repeatable.
- Recommended fix: Add Flyway or Liquibase migrations and disable Hibernate schema mutation outside local development.

## DEF-006

- Severity: MEDIUM
- Summary: Structured logs do not include event ID or aggregate ID fields globally.
- Requirement impacted: REQ-024 and observability requirements.
- Evidence: `logback-spring.xml` includes timestamp, level, service, correlation ID, logger, and message. It does not include event ID or aggregate ID MDC fields.
- Expected: Logs include event ID and aggregate ID when applicable.
- Actual: Event context is not globally represented in log format.
- Release impact: Async debugging is harder when tracing event processing.
- Recommended fix: Add event ID and aggregate ID MDC keys in event handlers and log pattern.

## DEF-007

- Severity: MEDIUM
- Summary: CloudWatch dashboards and alarms are not implemented.
- Requirement impacted: REQ-026, AC-029.
- Evidence: Terraform has core resource scaffolding but no CloudWatch dashboard or alarm resources for queue depth, DLQ depth, latency, or consumer failures.
- Expected: CloudWatch operational metrics and alarms are configured.
- Actual: Not implemented.
- Release impact: Operators lack required cloud visibility.
- Recommended fix: Add CloudWatch alarms and dashboard Terraform resources.

## DEF-008

- Severity: LOW
- Summary: Inventory API response omits `updatedAt`.
- Requirement impacted: API contract for `GET /api/inventory/{productId}`.
- Evidence: `InventoryResponse` contains `productId`, `availableQuantity`, and `reservedQuantity`; API contract includes `updatedAt`.
- Expected: Response includes `updatedAt`.
- Actual: `updatedAt` omitted.
- Release impact: Minor API contract mismatch.
- Recommended fix: Expose `updatedAt` from `InventoryItem` and add API contract test.
